# FixNote — концепт продукта и архитектуры

> Статус: v0.6 — решения ревью 1–4 внесены (см. раздел 10). M0 и M1 готовы. Web — полноценная платформа. Desktop — Windows first. После согласования разбиваем на ADR (docs/adr/) и спеки фич (docs/specs/).

---

## 1. Позиционирование

**Private personal memory.**
«Записывайте как думаете. Приложение само помогает вспомнить нужное, показывает источники и никогда не переписывает вашу память без разрешения».

Три обещания, из которых вытекает каждое продуктовое решение:

| Обещание | Что это значит в продукте | Что это запрещает |
|---|---|---|
| **Zero-maintenance** | Пишешь в Inbox, структура предлагается позже. Любое наведение порядка — предложение с approve/reject/undo. | Обязательные папки/теги/шаблоны при создании. Базы-конструкторы. |
| **Вспомнить, а не искать** | Гибридный поиск по смыслу + время + контекст. Ответ всегда с цитатой до фрагмента. | Граф связей как главный экран. Уверенный AI без источников. |
| **Контроль** | Данные шифруются на клиенте. Пользователь выбирает, где живёт AI (локально / наше облако / свой ключ). Оффлайн — норма, а не деградация. | Тихое обучение на данных, тихая автоправка заметок. |

Где **не** конкурируем: «всё-в-одном» workspace, суммаризация встреч, граф-как-витрина, ещё один Notion-конструктор.

Референсы по простоте: **Bear** (сайдбар, чистый редактор, теги без обязаловки). Референсы по AI-паттернам: картинки 1–5 из брифа (стартовый экран, properties-блок, daily note, selection-popover, spotlight).

## 2. Пользователь и сценарии (JTBD)

Первичный пользователь — один человек, личные заметки, 2–3 устройства (мак + браузер + позже телефон). Не команда.

| Job | Боль сейчас | Наше решение | Фича |
|---|---|---|---|
| Быстро сохранить мысль | Надо выбрать папку/тип/теги | Единый Inbox, голос/текст/ссылка одним жестом | Quick Capture, Voice, Paste-to-card |
| Вернуться к старому | Не помню формулировку и место | Поиск по смыслу + «когда» + «о чём» | Hybrid search, Spotlight, Recents |
| Понять, откуда ответ | AI смешивает источники | Цитаты до фрагмента, клик → заметка с подсветкой, индикатор уверенности | Chat with citations |
| Доверить базе личное | Страх утечки/обучения | E2E-шифрование, явный выбор AI-провайдера, журнал AI-действий | Privacy modes, Audit log |
| Навести порядок | Система превращается в проект | Пакетные предложения раз в N дней, approve/reject, undo | Tidy |

## 3. Продукт: экраны и фичи

### 3.1 Каркас (три колонки, как Bear)

```
┌──────────┬──────────────────────────────┬──────────────┐
│ Sidebar  │ Content                      │ AI Chat      │
│ поиск    │ Home / Note / Daily          │ (выезжает)   │
│ папки    │                              │ scope-бейдж  │
│ теги     │                              │ сообщения    │
│ Inbox    │                              │ цитаты       │
└──────────┴──────────────────────────────┴──────────────┘
                 [ Quick input снизу ]
```

- **Sidebar**: поиск, Inbox, Daily, папки (дерево), теги (авто-собираются из `#tag` в тексте, как в Bear), «Недавние». Папки — опциональны, Inbox — по умолчанию.
- **Content**: Home (стартовый экран) или открытая заметка. Табы как в референсе 2 — nice-to-have, не MVP.
- **AI Chat**: правая панель, `⌘J`. Единый чат на всё приложение (см. 4.1).
- **Quick input** снизу по центру: текст → «что это: заметка или вопрос?» решается кнопкой/хоткеем (`Enter` — заметка в Inbox, `⌘Enter` — спросить). Микрофон рядом.

### 3.2 Home (стартовый экран, референс 1)

- Заголовок-приветствие + Bloub (см. 4.6) как «присутствие» ассистента.
- Строка фильтров: `Все / Inbox / Папка ▾ / Тип ▾ / Период ▾` + поиск.
- Сетка карточек последних заметок, **infinite scroll** (cursor по `updated_at`). Карточка показывает превью в зависимости от типа контента: текст / чеклист / таблица / ссылка-карточка / голосовая (с длительностью).
- Quick input внизу.

### 3.3 Редактор заметки

- **Содержимое заметки — Markdown-строка.** Форматирование уровня Telegram: жирный, курсив, зачёркнутый, код, ссылки, списки, чекбоксы, заголовки, цитаты. Никаких блоков-баз, колонок, вложенных страниц.
- Редактор — Tiptap в минимальной конфигурации (StarterKit + markdown in/out). Нужен ради selection-popover, highlight и карточек ссылок; для всего остального это обычный текст. Markdown-шорткаты (`#`, `-`, `[ ]`, `>`, ``` ``` ```).
- **Properties-блок** сверху (референс 2): `title`, `tags`, произвольные `key: value`. Скрыт, если пуст. Это наш «frontmatter», не база данных.
- Дополнительно: highlight, wiki-ссылки `[[...]]` на другие заметки, изображение, embed-карточка. Таблицы — не MVP.
- **Paste-to-card**: вставил URL → определяем тип (YouTube/Vimeo, изображение, X/Instagram/TikTok, обычная страница, PDF) → рендерим карточку с OG-метаданными. Метаданные тянет edge-функция (CORS), в local-only режиме — Tauri сам.
- **Selection AI popover** (референс 4): выделил текст → плавающий инпут «что сделать?» + быстрые действия: *Переписать / Переформатировать / Сократить / Удалить / Начать новую заметку об этом*. Результат показывается как **diff с Accept/Reject**, никогда не применяется сам.
- **Daily note** (референс 3): `⌘D` открывает/создаёт заметку на сегодня, шаблон минимальный (Tasks / Notes). Незакрытые чекбоксы предлагаются перенести на завтра (предложение, не автоматика).

### 3.4 Spotlight (референс 5)

`⌘K` — палитра: Recents (последние 10), fuzzy-поиск по заголовкам, семантический поиск при ≥3 словах, команды («новая заметка», «daily», «переключить папку»). Работает везде, в том числе из редактора.

### 3.5 Поиск и фильтрация

Гибрид: **FTS5 (BM25) + вектор (cosine) + recency boost**, объединение через Reciprocal Rank Fusion. Фильтры: папка, тег, тип, период, «содержит ссылку/голос». Всё считается **локально** — поиск работает оффлайн.

### 3.6 Шеринг

«Поделиться» → создаём **снапшот** заметки (рендер в HTML + Markdown), публикуем по токен-ссылке. Для зашифрованной заметки это явное действие «расшифровать копию и опубликовать» с понятным текстом. Отзыв ссылки, срок жизни. Живая синхронизация расшаренной заметки — не MVP.

### 3.7 Импорт

Markdown внутри = импорт «перетащи папку». Импортёр сохраняет структуру папок, `#теги` и frontmatter-свойства, изображения кладёт во вложения. Пресеты: **Obsidian/любая Markdown-папка**, **Bear** (TextBundle/Markdown), **Notion** (Markdown + CSV, страницы → заметки, базы → заметки с properties), **Evernote** (ENEX → Markdown через готовую библиотеку). Всё импортированное попадает в Inbox с пометкой источника, Tidy потом предлагает порядок.

### 3.8 Локализация

EN / ES / RU с первого дня: `i18next` + ICU-плюрализация, язык интерфейса отдельно от языка заметок. Whisper и embedding-модель — мультиязычные (см. 5).

## 4. AI-слой

### 4.1 Единый чат со скоупами

Один тред на всё приложение. У каждого сообщения есть `scope`:

```
scope = { kind: 'all' } | { kind: 'folder', id } | { kind: 'note', id } | { kind: 'selection', noteId, range }
```

- Скоуп меняется автоматически по контексту (открыл заметку → скоуп `note`) или вручную в бейдже над инпутом.
- При смене скоупа в ленту вставляется **разделитель** «— теперь в контексте: *Books / Story* —». Это системное сообщение, оно хранится в истории.
- Retrieval всегда ограничен скоупом; пользователь может расширить одной кнопкой «искать во всех заметках».

### 4.2 Ответы с источниками

Каждый ответ содержит `citations[]: { noteId, chunkId, quote }`. В UI — чипы-источники; клик → открывает заметку с подсветкой фрагмента. Если релевантных фрагментов нет — ассистент говорит «в заметках этого нет» вместо выдумки. Индикатор уверенности: `high / medium / low` из score retrieval + self-check промпта.

### 4.3 Голос

- Одна кнопка микрофона в Quick input и в заметке. Долгое нажатие / `⌘⇧V`.
- Результат: транскрипт → «в новую заметку» / «дописать в текущую» / «спросить». По умолчанию из Home — новая заметка в Inbox, из заметки — дописать в конец.
- Сырой транскрипт всегда сохраняется; AI-«причёсывание» (убрать «эээ», разбить на пункты) — опция с diff.

### 4.4 Tidy — автонаведение порядка

Фоновый процесс раз в N дней / по кнопке. Формирует **пакет предложений**:

- перенести заметку в папку / предложить новую папку, когда в Inbox ≥ N похожих заметок;
- добавить/убрать теги;
- предложить заголовок безымянной заметке;
- слить дубликаты; разбить длинную заметку;
- связать заметки (`[[wiki-link]]`).

UI: список карточек с Approve / Reject / Approve all, каждая применённая — с Undo. Заметка не меняется без клика. Все действия пишутся в **AI audit log** («что, когда, каким провайдером, отменить»).

### 4.5 Автоструктурирование при вводе

Голосовой дамп или длинная вставка → предложение «оформить как заметку» (заголовок, пункты, properties). Diff, Accept/Reject. Не запускается само на коротких заметках.

### 4.6 Bloub

[jeremy-prt/bloub](https://github.com/jeremy-prt/bloub) (MIT) — SVG-аватар, морфится между 14 состояниями. Написан на Vue 3, но **движок анимации framework-free** (`engine.sample(t)` — чистая функция времени), поэтому портируем движок как есть, обёртку пишем на React.

Состояния маппим на AI-статусы: `idle` (Home), `listening` (запись голоса), `thinking` (retrieval + генерация), `speaking` (стримится ответ), `done`, `error`, `offline`. Живёт в Home по центру и в мини-размере в шапке чата.

### 4.7 Провайдеры моделей

Все нужные нам провайдеры (DeepSeek, OpenRouter, Groq, OpenAI, Ollama) говорят по одному OpenAI-совместимому HTTP-протоколу. Поэтому **никакого SDK-слоя**: один клиент с конфигом `{ baseURL, apiKey, model }`, стриминг через SSE, structured output через JSON-режим. Смена провайдера = смена URL.

Эмбеддинги и голос **всегда на устройстве** (Rust): сервер никогда не видит открытый текст заметок.

| Режим | LLM | Embeddings | Whisper | Кто платит |
|---|---|---|---|---|
| **Default** | DeepSeek через наш edge-прокси (в LLM уходят только найденные фрагменты) | fastembed в Rust | whisper.cpp в Rust | мы, лимиты по тарифу |
| **BYOK** | любой OpenAI-совместимый URL + ключ, ключ хранится в keychain | то же | то же | пользователь |
| **Local-only** | Ollama на localhost, синк выключен | то же | то же | никто |

Смена embedding-модели = реиндекс (фоновый, с прогрессом).

### 4.8 MCP

Заметки — контекст для других ассистентов (Claude Desktop, Cursor и т.д.):

- **Local MCP server** (stdio) — отдельный бинарь/сайдкар `fixnote-mcp`, читает локальную БД напрямую. Работает в local-only режиме.
- **Remote MCP** (HTTP + OAuth через Supabase Auth) — позже.
- Tools: `search_notes(query, scope?)`, `get_note(id)`, `create_note(content, folder?)`, `append_to_note(id, content)`, `list_recent(n)`, `daily_note(date)`.
- Каждый вызов извне попадает в AI audit log; запись через MCP по умолчанию идёт в Inbox с пометкой источника.

Экспорт: Markdown-папка + JSON целиком, в один клик, всегда. Это часть обещания «контроль».

### 4.9 Каналы захвата: Telegram-бот

Идея: накидывать мысли в бота, они появляются в Inbox приложения. Проектируем как общий механизм `capture_channels`, первый канал — Telegram, позже другие мессенджеры и email-in.

- **Привязка**: в настройках «Подключить Telegram» → deep link `t.me/<bot>?start=<code>` → edge-функция связывает `chat_id` с `user_id`.
- **Совместимость с шифрованием**: у пользователя есть пара ключей (публичный хранится на сервере). Бот запечатывает каждое сообщение публичным ключом (libsodium `crypto_box_seal`) и кладёт в `inbox_items`. Расшифровать может только приложение — оно забирает items, превращает в заметки в Inbox с пометкой «из Telegram» и удаляет с сервера.
- **Голосовые**: бот транскрибирует их через Whisper API до запечатывания (аудио и так уже у Telegram, приватность не ухудшается). Сохраняем и аудио, и текст.
- **Ссылки/фото**: как обычная вставка — unfurl-карточка / вложение.
- Бот **только пишет**; чтения заметок через Telegram нет, это не второй клиент.

## 5. Как обыгрываем тренды

| Тренд | Как это выглядит у нас |
|---|---|
| Папки → semantic retrieval | Папки есть, но не обязательны. Главный вход — Spotlight и вопрос в чат. Поиск понимает «то, что я записал про CSS на прошлой неделе». Граф связей не строим. |
| Облачный AI → выбор модели | Три режима (Cloud / BYOK / Local), переключаются в настройках. На онбординге — «где будет работать ваш AI?» с честным описанием. |
| Ручная система → zero-maintenance | Inbox по умолчанию. Tidy как пакет предложений. Любая структура обратима (undo). Нет шаблонов-обязаловки. |
| Закрытое приложение → MCP/коннекторы | MCP-сервер и экспорт в Markdown с первой публичной версии. Это канал дистрибуции: «подключи свои заметки к Claude». |

## 6. Архитектура

### 6.1 Принцип: local-first

Источник истины — **локальная БД на устройстве**. Сервер — реле синхронизации, хранилище зашифрованных данных и (опционально) AI-прокси. Приложение полностью работает без сети; синк догоняет при появлении интернета.

```
┌───────────── Client: один React-код ───────────────┐
│ UI ── core (domain, sync, crypto, retrieval, tidy) │
│         │ Platform interface (sql/embed/stt/keys)  │
│   Tauri: SQLite via rusqlite, fastembed (Rust),    │
│          whisper.cpp (Rust), OS keychain           │
│   Web:   SQLite WASM (OPFS), transformers.js       │
│          (WebGPU/WASM), transcribe edge, IndexedDB │
└──────────────┼─────────────────────────────────────┘
               │ ciphertext + metadata
┌──────────────▼── Supabase ─────────────────────────┐
│ Auth │ Postgres (+RLS) │ Realtime │ Storage │       │
│ Edge Functions: llm-proxy, unfurl, share,          │
│                 telegram-webhook, transcribe (web)  │
└────────────────────────────────────────────────────┘
               │ только найденные фрагменты
            DeepSeek (OpenAI-compatible)
```

### 6.2 Хранение и синхронизация

- **Содержимое заметки = Markdown-строка.** Никаких CRDT: для одного человека одновременные правки на двух устройствах — редкость, и ради неё не стоит тащить Yjs.
- **Синк — optimistic concurrency по версии.** У заметки есть `version`. Клиент шлёт `{ id, base_version, content, ... }`; сервер (RPC-функция в Postgres) применяет, если `base_version == version`, иначе возвращает `409` с актуальной версией.
- **Конфликт**: клиент делает трёхсторонний merge текста (`diff3` / `diff-match-patch`: база → моя → чужая). Если merge чистый — отправляет результат. Если нет — сохраняет свою версию как отдельную заметку «Конфликтная копия (устройство, дата)» рядом с оригиналом. Ничего не теряется, пользователь разбирается сам.
- Удаление — soft delete (`deleted_at`), корзина 30 дней.
- Realtime-подписка на `notes` по `user_id` для мгновенного появления правок с другого устройства; при старте и по таймеру — pull по `updated_at > last_sync`.
- **Локально — SQLite на обеих платформах, одна схема, один SQL.** `packages/core` содержит всю логику (схема, миграции, запросы, синк, ранжирование) на TypeScript и работает через узкий интерфейс `SqlDriver { execute, query }`. Адаптеры тонкие: Tauri → две свои команды `db_execute` / `db_query` на `rusqlite` (bundled SQLite с FTS5) с **одним соединением** под мьютексом, Web → `@sqlite.org/sqlite-wasm` в Worker поверх OPFS (VFS `opfs-sahpool`, не требует COOP/COEP). Общая обёртка `createSqlDriver` в core выстраивает все вызовы в очередь, поэтому транзакция держит соединение до COMMIT. `tauri-plugin-sql` отклонён: у него пул соединений, и BEGIN/COMMIT могут уйти в разные соединения. Ни одна доменная строка не дублируется в Rust.
- FTS5 для полнотекста по колонке `search_text` (Markdown, очищенный до текста: сниппеты без разметки, блоки кода остаются в индексе), токенайзер `unicode61 remove_diacritics 2` (регистр и диакритика ru/es/en). Вектора как BLOB, brute-force cosine в TS (typed arrays): для личной базы (десятки тысяч чанков) это единицы миллисекунд, расширений не нужно.
- **Локальная БД хранится в открытом виде** (FTS-индекс иначе невозможен), защищена ОС: FileVault/BitLocker на десктопе, per-origin OPFS в браузере. Шифруется всё, что покидает устройство.
- **Вектора синхронизируются как зашифрованные блобы** (`note_vectors`: note_id, model, sealed blob). Эмбеддинг считается один раз на том устройстве, которое первым увидело правку, остальные качают. Новое устройство не пересчитывает базу с нуля.
- Вложения (изображения, аудио) — Supabase Storage, зашифрованы на клиенте, локальный кеш в app-data.

Почему не PowerSync/ElectricSQL: они хороши, но плохо дружат с клиентским шифрованием; версия + diff3 — минимальная и предсказуемая схема.

### 6.3 Шифрование и AI: как совместить

Проблема: E2E-шифрование ⟂ серверный AI. Решение: **сервер никогда не видит открытый текст**, весь тяжёлый AI (эмбеддинги, поиск, Whisper) живёт на устройстве, а в LLM уходят только найденные фрагменты по конкретному запросу.

**Вход и ключи разделены. Паролей нет вообще.**

1. **Вход**: email + 6-значный код (Supabase Auth email-OTP). Это идентификация пользователя для синка, платежей и контакта. Google/Apple — позже, схему не ломают.
2. **Master Key (MK)** генерируется случайно на устройстве при первом входе. Desktop: OS keychain (`tauri-plugin-stronghold` / keyring). Web: MK завёрнут non-extractable AES-ключом из WebCrypto, обёртка лежит в IndexedDB — сырой ключ в storage не попадает. Пользователь ничего не придумывает и не запоминает.
3. Из MK выводится пара ключей `(pk, sk)` (X25519). `pk` хранится на сервере — им бот и будущие каналы захвата запечатывают входящие.
4. Каждая заметка шифруется своим **Data Key (DK)** (XChaCha20-Poly1305), DK завёрнут в MK. Сервер хранит ciphertext + завёрнутые DK.
5. **Recovery-фраза (12 слов, BIP39)** = MK. Показывается один раз после первого входа, просим сохранить и подтвердить 3 случайных слова. Это единственная резервная копия ключа.
6. **Второе устройство**: вход по коду → «введи recovery-фразу» или «отсканируй QR на первом устройстве» (QR несёт MK напрямую, сервер не участвует). Для web без камеры — тот же QR показывается как 6-словный код для ручного ввода.
7. **Потеря фразы и всех устройств** = заметки не восстановить, это говорится прямо на онбординге. Opt-in «хранить резервный ключ у нас» (выключен по умолчанию, с честным текстом «тогда мы теоретически можем прочитать заметки») — для тех, кому удобство важнее.

**Что видит сервер**: шифротекст заметок, метаданные (папка, даты, теги), вектора не видит вообще (они локальные), фрагменты заметок — только транзитом через `llm-proxy` при запросе в чат, без логирования.

**Local-only** (настройка «заметки не покидают устройство»): синк и прокси выключены, LLM — Ollama на localhost. Каналы захвата в этом режиме не работают, это честно показываем.

**Где живёт LLM**: DeepSeek API размещён в Китае. В настройках даём выбор прокси-провайдера (DeepSeek напрямую / через OpenRouter с EU-хостингом / Groq) и пишем, куда уходят фрагменты. Дефолт — то, что дешевле нам, но выбор виден.

#### Почему эмбеддинги на устройстве, а не на сервере

| Критерий | Cloud (сервер видит текст) | Private (на устройстве) |
|---|---|---|
| Первый запуск | Мгновенно | Модель ~120 MB + индексация (10k заметок ≈ минута на M1) |
| Несколько устройств | Один индекс на сервере | Синк зашифрованных векторов: считаем один раз |
| Tidy в фоне | Работает при закрытом приложении | Только при открытом |
| Оффлайн семантический поиск | Нет | Да |
| Web / мобилка | Легко | Web: WASM/WebGPU в 2–5× медленнее; мобилка: батарея |
| Стоимость нам | Копейки за токены, но сервер надо держать | Ноль |
| Приватность | Шифрование «от утечки базы», мы читать можем; Vault, GDPR | Настоящее E2E, позиционирование честное |
| Бэкенд | + embed, tidy-воркеры, Vault | Только llm-proxy |

Решение: Private по умолчанию на обеих платформах. Web считает эмбеддинги через transformers.js (WebGPU, fallback WASM) в Worker. Благодаря синку зашифрованных векторов web-клиенту обычно нужно эмбеддить только свои новые заметки и поисковые запросы, а не всю базу. Интерфейс `Embedder` в core оставляет возможность добавить Cloud-эмбеддинги как opt-in.

**Одна модель — один ONNX-файл.** Вектора с desktop и web должны быть побитово совместимы, поэтому обе платформы грузят один и тот же ONNX-артефакт `multilingual-e5-small` (int8) с нашего CDN: desktop через `ort` (fastembed с user-defined моделью), web через `onnxruntime-web`. Смена файла = смена `model` в `note_vectors` и реиндекс.

### 6.4 Модель данных (ядро)

```
users            id, email, pk, escrow_mk? (только при opt-in)
folders          id, user_id, parent_id?, name, sort, updated_at, deleted_at
notes            id, user_id, folder_id?, type (text|daily|voice|link), version,
                 wrapped_dk, content (encrypted Markdown), properties (encrypted JSON),
                 source (app|telegram|mcp), created_at, updated_at, deleted_at
tags             id, user_id, name           note_tags (note_id, tag_id)
chunks           (только локально) note_id, ord, text_hash, text, embedding blob, model
note_vectors     note_id, model, sealed_blob, updated_at
attachments      id, note_id, storage_path, mime, size, wrapped_key
chat_messages    id, user_id, role, scope (json), content (encrypted), citations (json), created_at
suggestions      id, user_id, kind, payload (json), status (pending|accepted|rejected), created_at, applied_at
ai_audit_log     id, user_id, action, provider, note_ids[], reversible, created_at
shares           id, note_id, token, rendered_html (plaintext by explicit consent), expires_at
capture_channels id, user_id, kind (telegram), external_id (chat_id), created_at
inbox_items      id, user_id, channel_id, sealed_payload, created_at   -- удаляется после забора клиентом
```

RLS: `user_id = auth.uid()` на всех таблицах. Никаких серверных join'ов по plaintext.

### 6.5 Retrieval pipeline

1. Чанкинг по блокам редактора (~300–500 токенов, с перекрытием) при сохранении, инкрементально по `text_hash`.
2. Эмбеддинг локально (fastembed, `multilingual-e5-small`).
3. Запрос: FTS5 top-50 + cosine top-50 → RRF → recency boost → фильтр по scope → top-8 в промпт.
4. Промпт требует ответить только по фрагментам и вернуть `citations` структурированно (JSON-режим).

### 6.6 Платформенные адаптеры

Единственное место, где desktop и web различаются. Всё остальное — общий код.

| Возможность | Интерфейс в `core` | Tauri (desktop) | Web (PWA) |
|---|---|---|---|
| Локальная БД | `SqlDriver` | `rusqlite`, одно соединение, WAL | `sqlite-wasm` + OPFS (`opfs-sahpool`) в Worker; вторая вкладка → баннер «изменения не сохранятся» |
| Эмбеддинги | `Embedder` | fastembed (`ort`) в Rust | transformers.js, WebGPU/WASM в Worker |
| Голос → текст | `Transcriber` | whisper.cpp в Rust, локально | edge `transcribe` (Whisper API); честно помечено «аудио уходит на сервер»; локальный whisper через WebGPU — позже |
| Хранение MK | `KeyStore` | OS keychain | WebCrypto non-extractable wrap + IndexedDB |
| Крипто | `libsodium-wrappers` (WASM) | то же | то же |
| Unfurl ссылок | `Unfurler` | edge `unfurl`; в local-only — Rust `reqwest` | edge `unfurl` |
| Файлы/вложения | `BlobStore` | app-data dir | OPFS |
| Оффлайн | — | нативно | Service Worker (app shell + модели в Cache API) |
| MCP | — | локальный stdio-сервер над той же SQLite | только remote MCP (позже) |
| Local-only режим | — | да | нет (нет Ollama из браузера, нет локального Whisper) — режим скрыт |
| Глобальный хоткей / трей | — | да | нет |

Web-версия — статика (Cloudflare Pages / Vercel), PWA с установкой. Ограничения web показываются в настройках как «недоступно в браузере», а не прячутся.

## 9. Открытые вопросы

1. **Тариф**: что лимитируем — число LLM-запросов через наш прокси в месяц, объём Storage для вложений, число устройств?
2. **Модель Whisper на десктопе**: `small` (~500 MB, хорошее качество ru/es) или `base` (~150 MB, хуже на русском)? Предлагаю `small`, качать при первом включении микрофона.
3. **Название бота** и нужен ли ему ответ «сохранено» с ссылкой в приложение.
4. **Подпись Windows-сборок**: без сертификата SmartScreen предупреждает при первом запуске. Варианты: OV-сертификат, Azure Trusted Signing (дешевле, но требует юрлица/истории), или пока без подписи для первых пользователей.
5. **Хостинг web-версии** (Cloudflare Pages / Vercel / Netlify) — нужен для деплоя из CI.
